# Shared laptop AI for Unforked

The owner approved the shared-laptop approach in the preceding discussion and asked to start integration after installing and testing Qwen3.5 4B. Keep the existing Chrome extension, hosted GitHub authentication, public repository retrieval and invitation boundary. Replace only the selected generation provider.

## Design

Use a Node gateway on `127.0.0.1:11435`, connecting to Ollama on `127.0.0.1:11434`. The gateway accepts a server-to-server bearer secret; the hosted Worker keeps that secret, never the extension. Only bounded schema/prompt generation requests reach the fixed `qwen3.5:4b` model. GitHub credentials stay in the Worker.

One GPU request runs at a time; at most two wait. Cancellation removes waiting requests and propagates to active Ollama fetches. Total queue/inference timeout is 120 seconds. Busy, offline, timeout and invalid output have distinct safe errors. No automatic Gemini fallback or inference retry.

The measured 32768-token slot fits entirely on the RTX4060: about5436MiB used,2521MiB free,100%GPU. Use that bounded slot, thinking disabled, at most1200 output tokens per call. Keep the existing30000 conservative cumulative input-byte budget, at most3 model calls and3000 total output tokens per action. Bound prompt+schema+1024 overhead+output to the context slot as well. Retain citations, repo and issue validation.

A development Quick Tunnel exposes only the authenticated gateway. Raw Ollama stays loopback. No new domain, paid service or firewall opening is required for this small beta. Quick Tunnel hostnames change on restart and have no uptime guarantee; public rollout needs a stable endpoint. A launcher starts/stops gateway+tunnel and updates the hosted endpoint through the owner's existing Wrangler login. Remote URL/key configuration uses protected stdin; never put secrets in command arguments or logs.

Provider selection is explicit: `AI_PROVIDER=gemini|ollama`. Preserve the working Gemini configuration for deliberate rollback. Local health and response metadata identify laptop generation; the extension shows local/offline state. Privacy disclosures explain that selected requests/repo evidence are processed in RAM on the beta owner's laptop. No raw prompts/output, keys or GitHub tokens enter application logs or D1.

Local quotas are request fairness controls, separate from the unchanged Gemini reference-cost budget:100 owner actions/day,20 per invited friend/day,1000 local actions/month shared. Existing Gemini usage remains intact. Failed/cancelled local attempts retain their action slot, disclosed in the operator guide. No friend is invited implicitly.

Acceptance refinement: real 4B probes exposed truncated verbose ranking, invented/duplicate identities and citations mixed across candidates. Ranking uses short bounded fields. Local mode selects a zero-based candidate index; its generation schema binds each index to that candidate's source-ID enum. The backend supplies the verified repository identity/date and removes duplicate selections with a visible limitation. Existing full evidence/issue validation remains. The dynamic schema is included in the input budget and its 12KB transport ceiling. Generic answers still need broader quality evaluation.

## Acceptance

Unauthorized or oversized gateway requests never reach Ollama. Four simultaneous calls run one, queue two and reject the fourth. Cancelled queued work is never started. Unknown/missing provider config fails closed. Laptop offline never calls Google. Local usage cannot consume/reset Gemini accounting. Existing demo and Gemini flows pass.
